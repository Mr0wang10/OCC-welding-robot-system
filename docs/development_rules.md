# OCC_MFC 开发规范

## 开发注意事项

### 编译输出目录

- 不要随意修改或删除 x64/ 下的构建产物。
- 仅在明确需要清理或重建时允许修改。

------

### RC 资源文件

修改 .rc 文件时：

- 优先使用 Visual Studio 资源编辑器
- 禁止随意改变文件编码
- 禁止使用 UTF-8 BOM

否则可能导致：

undefined keyword or key name

等资源编译错误。

------

### DEBUG_NEW 与 OCCT

MFC DEBUG 模式下：

DEBUG_NEW 可能与 OpenCascade 的：

- Handle
- Standard_Transient
- 

发生冲突。

项目中部分 OCCT include 前后已使用：

```cpp
#undef new
```

及恢复逻辑。

修改相关代码时必须保留该机制。

------

### OCC_MFCDoc.cpp

该文件包含大量：

- 机器人运动学
- 坐标变换
- TCP 标定
- 手眼标定

相关计算。

修改前必须确认：

- 单位一致性
- 坐标系定义
- 欧拉角顺序
- TCP 标定矩阵含义

禁止未经分析直接修改矩阵运算逻辑。

------

### UI 联动保护

控制面板编辑框存在联动关系。

新增回填逻辑时：

必须使用：

```cpp
m_bIsUpdating
```

防止递归触发事件。

------

### 测试要求

当前项目暂无自动化测试。

涉及以下模块修改时：

- 运动学
- STEP加载
- 模型显示
- 视图刷新
- UI交互

必须进行：

- 编译验证
- 运行验证

------

# 文件编码规范

## 编码要求

### C++ 文件

文件类型：

```text
.h
.cpp
```

要求：

```text
GBK (Code Page 936)
```

------

### RC 文件

文件类型：

```text
.rc
```

要求：

```text
GBK
无 UTF-8 BOM
```

------

### 行结束符

允许：

```text
LF
CRLF
```

------

### 编码操作要求

1. 所有项目文件使用 GBK 编码读写
2. 禁止将中文内容写入 UTF-8 文件
3. 出现乱码时优先检查编码
4. AGENTS.md 与 docs 文档保持 GBK 编码

------

# 代码注释规范

## 基本要求

新增、修改或重构代码时：

必须同步维护中文注释。

------

## 必须添加注释的内容

- 复杂逻辑
- 核心算法
- 数学公式
- 坐标变换
- 指针操作
- 内存管理
- 多线程逻辑
- OCCT 调用
- Eigen 调用
- OpenCV 调用
- 运动学流程
- 点云处理流程
- 焊缝识别流程

------

## 函数注释要求

新增函数必须说明：

- 功能
- 参数
- 返回值
- 关键逻辑

推荐格式：

```cpp
/**
 * @brief 提取STEP模型中的候选焊缝边
 * @param shape 输入CAD模型
 * @return 候选焊缝边列表
 */
```

------

## 注释维护要求

修改代码时：

- 更新失效注释
- 删除错误注释
- 保持注释与代码一致

禁止保留错误注释。

------

# 代码风格

- 保持现有缩进风格
- 保持现有命名风格
- MFC消息映射按功能分组
- 新增消息映射需添加用途说明

------

# Git 提交规范

## Commit Message 格式

```text
type: 简要描述
```

允许：

```text
feat
fix
refactor
docs
test
style
perf
chore
```

示例：

```text
feat: 新增STEP模型焊缝识别功能

fix: 修复OCCT窗口缩放显示异常

refactor: 重构机器人运动学模块

docs: 更新项目架构文档
```

禁止：

```text
update
fix bug
修改代码
优化代码
```

------

# 修改完成后输出

必须输出：

1. 修改的代码文件
2. 更新的文档文件
3. 修改内容摘要
4. 文档同步情况
5. 建议 Commit Message
